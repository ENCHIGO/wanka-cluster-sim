# 万卡集群模拟器

在浏览器里当一回大模型训练集群的值班工程师。

你要在期限和预算之内，把一个模型训完。开跑前先配集群：GPU 型号、卡数、网络、存储，
再定并行策略（TP / PP / DP / EP）、全局批次、激活重计算和 checkpoint 间隔。
开跑之后，一万张卡平均几个小时就坏一张：掉卡、ECC 错误、链路抖动、过热降频、loss 尖峰。
你要决定什么时候存盘、留多少热备、换不换慢节点、要不要回滚。

## 玩法

- **配置台**：右侧实时给出步时拆解、每卡显存、MFU、集群故障间隔、预计工期和花费。显存溢出或切分不合法时不能开跑。
- **GPU 墙**：每格一张卡，每 8 格一个节点。琥珀色是降频的慢节点，点它会先存 checkpoint 再用热备换下。
- **故障**：作业回滚到最近的 checkpoint。有热备约 10 分钟恢复；没有热备要原地等维修约 3 小时。换下的节点 1–3 天后修好回到热备池。
- **loss 尖峰**：自动暂停，二选一：回滚跳过数据，或继续观察（约四成概率发散，尖峰后存的 checkpoint 作废）。
- **结算**：按期完成得 1 星；花费不超过预算 85% 加 1 星；Goodput ≥ 85% 加 1 星。

关卡：入职第一周（70B）、万卡 405B、MoE 冲刺（671B-A37B）。

## 运行

纯静态页面，没有构建步骤：

```bash
npm start          # 等价于 python3 -m http.server 8000
# 打开 http://localhost:8000
npm test           # 性能模型的单元测试（Node 18+）
```

## 代码结构

- `src/sim.js`：性能与可靠性模型，纯函数，可在 Node 里测试
- `src/game.js`：游戏循环、事件、GPU 墙和图表的绘制
- `index.html`：页面结构与样式
- `tests/`：模型测试

## 模型说明

数量级对、取舍有意思，不追求逐包仿真：

- 计算时间 = 6 × 激活参数 × token / (卡数 × 峰值 × 内核效率)，重计算多算 1/3
- TP 每层 4 次激活集合通信，≤8 卡走 NVLink，否则走网卡
- EP 的 all-to-all 按 top-k 拷贝计流量；每卡专家越多，GEMM 越碎、效率越低
- 流水线气泡 = (PP−1) / 微批次数；DP 梯度同步约 70% 与反向重叠
- 显存：bf16 权重 + fp32 梯度 + Adam 状态按 DP 切分（ZeRO-1）+ 激活
- 故障率按单卡 MTBF 线性放大；checkpoint 间隔可对照 Young 公式 √(2·C·MTBF)
- 全局批次超过临界批次后 token 利用率递减；loss 用 Chinchilla 拟合
