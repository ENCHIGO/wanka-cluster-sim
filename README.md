# 万卡集群模拟器

在浏览器里当一回大模型集群的值班工程师。有两种玩法：训练和推理部署。

**训练**：你要在期限和预算之内把一个模型训完。开跑前先配集群：从 20 种加速卡里挑一种、卡数、训练精度（BF16 / FP8 / FP4）、网络、存储，
再定并行策略（TP / PP / DP / EP）、全局批次、激活重计算、存盘间隔和备机数量。
开跑之后，一万张卡平均几个小时就坏一张：掉卡、ECC 错误、链路抖动、过热降频、loss 尖峰。
你要决定什么时候存盘、留多少备机、换不换慢机器、要不要回滚。

**推理部署**：挑一个前沿开源模型（或者从 Hugging Face 导入），从 20 种加速卡里挑一种，在推理大厅 B 的 1,024 张卡上把它部署出去，
扛住一整天的线上流量。每个请求的首 token 和每 token 延迟都要在 SLO 内，全天达标率要到 99%，钱还不能超预算。

## 训练

- **开局配置**：左边选任务，中间配集群，右边实时给出工期、花费、单步耗时拆解、每卡显存，
  集群负责人老周会指出配置里的问题，还会搜一遍别的卡、精度和切分，给一套更快或更省的配置，一键就能照着改。
  配置不成立（除不尽、显存不够、这单不让用这种卡）时不能开跑。
- **换卡**：卡型列表可以按卡名、厂商（中英文都行）、互联、显存搜，比如 NVL72、HBM4、昇腾；
  列表里每种卡都按现在的切分算好了工期和花费。和推理部署用的是同一张规格表。
- **值班**：机房是一个等距视角的沙盘。8 卡一台机器，4 台一个机柜，两排背靠背一组，
  每个机柜顶上的四颗灯就是四台机器。降频和故障的机柜上会立起标记，点机柜能看每台机器的状态，
  降频的可以一键换下（先存盘，再用备机顶上重启）。
- **故障**：作业回滚到最近一次存盘。有备机大约 10 分钟恢复；备机用光了，就得停 3 小时等现场修。
  坏机送修 12–48 小时后回到备机池，所以卡越多，需要的备机越多，开局预估会按坏机速度算出该留几台。
- **过热降频**：同步训练要等最慢的那台，全集群按 0.62 倍速跑。七成会在 2–8 小时内自己降下来，
  剩下的要换。卡多了手动换不过来，可以在底栏打开“降频自动换下”（1 或 4 小时后自动换）。
- **loss 尖峰**：自动暂停，二选一：回滚并跳过这批数据，或者先观察（四成会发散，尖峰后的存盘作废）。
- **验收**：按期交付才评级。Goodput ≥ 85% 和花费 ≤ 预算 90% 两条都满足是 S，满足一条是 A，都不满足是 B。
  验收页有整局的时间线，还会把时间拆成有效训练、降频拖慢、重启、等维修、存盘、回滚几块。

快捷键：空格暂停，1/2/3 切速度，S 存盘，B 加备机，C 改配置，Esc 关掉机柜详情；loss 尖峰时按 1 或 2 选。

任务：

| 任务 | 难度 | 规模 | 看点 |
|---|---|---|---|
| 27B 稠密 | 入门 | 10T token，最多 4,096 卡，14 天 | 并行切分、训练精度、存盘间隔 |
| 35B-A3B 小 MoE | 进阶 | 24T token，最多 4,096 卡，12 天 | 算得快，通信成了大头：all-to-all 出不出 NVLink 域 |
| 国产算力 | 困难 | 744B-A40B，15T token，最多 16,384 卡，30 天 | 只能用昇腾：910C 没有 FP8 但有 384 卡超节点，950PR 能跑 FP4 但一台只有 8 卡 |
| 1.6T MoE 万卡 | 困难 | 1.6T-A49B，33T token，最多 16,384 卡，12 天 | 一两个小时坏一台：备机、存盘、FP8 还是 FP4、上不上 NVL72 |
| 2.8T MoE | 专家 | 2.8T-A104B，30T token，最多 16,384 卡，24 天 | 896 个专家选 16：EP 放进整柜，首批 Rubin / MI455X 只有 2,304 张 |

## 推理部署

- **选模型**：内置 12 个 2026 年 10 月前后的前沿开源模型：DeepSeek-V4-Pro / V4-Flash、Kimi-K3、Kimi-K2.5、
  Qwen3.8-2.4T-A95B、Qwen3.5-397B-A17B、Qwen3.6-35B-A3B / 27B、MiMo-V2.6-Pro、GLM-5.3、MiniMax-M3、gpt-oss-120b。
  也可以填 Hugging Face 仓库名，直接读它的 config.json；要先同意协议的模型、私有仓库，
  或者在 Claude 里打开时连不上 Hugging Face，就把 config.json 粘贴或拖进来。
  导入后算出总参数、激活参数、一个 64K 请求的 KV cache（认得 MLA、GQA、DeepSeek V4 的 CSA/HCA 压缩注意力、
  DSA 稀疏注意力、Gated DeltaNet / KDA 线性注意力、滑窗、MTP、FP8 / MXFP4 / INT4 原生权重），
  再把 20 种加速卡按每百万 token 的成本排一遍：每种卡几张放得下、一个副本能扛多少请求、每百万 token 多少钱。
- **加速卡**：NVIDIA L40S、RTX PRO 6000、H20、H100、H200、B200、B300、GB200 NVL72、GB300 NVL72、Rubin NVL72；
  AMD MI300X、MI355X、MI455X；Google TPU v6e、TPU v7；AWS Trainium2、Trainium3；华为昇腾 910C、950PR；Intel Gaudi 3。
  每种卡有显存、带宽、BF16 / FP8 / FP4 算力、scale-up 域（NVL72 柜内 72 卡走 NVLink，HGX 超过 8 卡就要走网卡）和每卡时价格。
  Rubin 和 MI455X 最省，但首批只到了两个柜（各 144 张），大模型扛高峰就得换别的卡。
- **部署方案**：三个任务：日常流量（入门，晚高峰 1,000 请求/秒）、发布会（困难，20:00 开场流量 10 分钟翻一倍）、
  长上下文 Agent（专家，平均上下文 64K token，八成命中前缀缓存）。配每个副本用什么卡、几张卡（1–72）、
  权重精度（BF16 / FP8 / FP4）、最大并发、KV cache 存不存 FP8、开不开 MTP 投机解码，再配扩缩容：
  最少 / 最多副本、目标负载、发布会前预扩到几个。右边按同样的规则把这一天先跑一遍，
  给出达标率、花费和一个副本的延迟曲线，老周会说哪里能改。预算和单价目标按模型定（见下面的模型说明），
  所以 27B 和 2.8T 的模型都有得玩。
- **线上值班**：还是机房沙盘，绿灯是在线的副本，蓝灯是冷启动中的，红灯是故障。
  冷启动要先把权重读进显存（Kimi-K3 在 GB300 上八卡一个副本要 10 分钟），所以流量涨得比扩容快就会排队。
  可以手动加副本、限流、改扩缩容；排队太长会自动暂停，让你选限流（拒掉一部分，保住后面的请求）还是硬扛。
- **复盘**：达标率过线才评 S/A/B，没过线是 C；每天花费不超预算、每百万输出 token 不超目标各算一条。
  复盘页会用当天的实际流量和故障换几种方案重跑一遍，告诉你改哪里能升一档。

快捷键：空格暂停，1/2/3 切速度，A 加 8 个副本，L 限流，C 改方案，Esc 关掉机柜详情；排队太长时按 1 或 2 选。

## 运行

纯静态页面，没有构建步骤：

```bash
npm start          # 等价于 python3 -m http.server 8000
# 打开 http://localhost:8000
npm test           # 性能模型、推理模型和机房排布的单元测试（Node 18+）
```

在线版：<https://enchigo.github.io/wanka-cluster-sim/>。推到 main 以后，GitHub Actions（`.github/workflows/pages.yml`）先跑测试，过了再发布到 GitHub Pages。

自己部署时，页面会直接从 `huggingface.co/<仓库>/resolve/main/config.json` 读配置；在 Claude 里打开时网页不能访问外部网站，只能粘贴。

## 代码结构

- `src/gpus.js`：20 种加速卡的规格表，训练和推理共用
- `src/sim.js`：训练的性能与可靠性模型，纯函数，可在 Node 里测试；老周的换卡建议也在这里
- `src/serve.js`：推理的模型：解析 config.json、估一个副本的吞吐和延迟，按分钟推进一天（扩缩容、冷启动、故障、排队、限流）
- `src/catalog.js`：内置模型的 config.json 关键字段，公开资料里没写全、按参数量反推的字段单独标出来
- `src/scene.js`：等距机房的排布和 canvas 渲染（机房本体缓存成一层，每帧只画灯、高亮和人）
- `src/game.js`：训练模式的游戏循环、事件、界面
- `src/serve-ui.js`：推理部署的四个页面和值班循环
- `src/ui.js`：两种模式共用的图标、格式化和控件
- `src/picker.js`：可以搜索的换卡弹层，两种模式共用
- `index.html`：页面结构与样式
- `tests/`：模型和排布的测试

## 模型说明

数量级对、取舍有意思，不追求逐包仿真。

训练：

- 计算时间 = 6 × 激活参数 × token / (卡数 × 所选精度的峰值 × 内核效率)，重计算多算 1/3。
  FP8 能跑到 FP8 峰值的 78%，FP4 能跑到 55%（量化开销、留在 BF16 的算子）；精度越低 loss 尖峰越多（FP8 1.3 倍，FP4 2 倍）。
  8 比特是 INT8 的卡（昇腾 910C、TPU v6e）不能用 FP8 训练，没有 4 比特张量核的不能用 FP4
- 内核效率再乘一个软件栈成熟度：CUDA 最高，ROCm、Neuron、CANN 和刚出的新卡打折（游戏值）
- TP 每层 4 次激活集合通信，在 scale-up 域里（HGX 一台 8 卡，NVL72 一柜 72 卡，TPU / 昇腾超节点更大）走 NVLink 这类互联，否则走网卡
- EP 的 all-to-all 按 top-k 拷贝计流量，EP×TP 在域里就走域内互联；每卡专家越多，GEMM 越碎、效率越低
- 网络带宽还要受卡上网卡的限制：H100 插 800G 也只有 400G；优化器一步的时间看显存带宽
- 流水线气泡 = (PP−1) / 微批次数；DP 梯度同步约 70% 与反向重叠
- 显存：bf16 权重 + fp32 梯度 + Adam 状态按 DP 切分（ZeRO-1）+ 激活
- 故障率按单卡 MTBF 线性放大；存盘间隔可对照 Young 公式 √(2·C·MTBF)
- 备机池按泊松分布估算用光的概率：送修中的机器 ≈ 坏机速度 × 平均送修时长
- 全局批次超过临界批次后 token 利用率递减；loss 用 Chinchilla 拟合
- 各任务的预算和期限按开局预估校准：把所有卡型、精度、卡数和切分搜一遍，挑好的配置能按期交还有余量，
  默认配置要改几处才行。Rubin、MI455X 每卡最快，但训练大厅里各只有 2,304 张

推理：

- 参数量按 config.json 逐层算：注意力（MLA、GQA、带输出门控的注意力、V4 的分组低秩输出投影、DSA 的索引器、
  线性注意力）、稠密 FFN、MoE 的路由专家（包括先投影到小维度再进专家的）、共享专家、词表
- 每层注意力分成几种：全注意力、稀疏注意力（KV 全存，每个 token 只看 index_topk 个）、滑窗（只存最近 sliding_window 个）、
  线性注意力（每个请求一份固定大小的状态）、V4 的 CSA / HCA（每 4 / 128 个 token 压成一条，再加 128 个 token 的滑窗）。
  KV cache、解码每步读的字节、注意力的算力都按层的种类分别算，所以长上下文时这些设计能省多少都体现得出来
- 权重精度：4 比特只压专家和 FFN（开源的 MXFP4 / NVFP4 / INT4 权重通常是这么做的），注意力和词表按 8 比特；
  只有带 FP4 张量核的卡（Blackwell、MI355X 以后、Rubin、昇腾 950、Trainium3）用 4 比特算得更快，别的卡只省显存
- 每卡显存 = 权重 / 卡数 + KV cache + 运行时开销（4 GB + 显存的 6%），剩下的决定能同时跑多少请求
- 解码一步 = 读权重（MoE 按这一批实际用到的专家算）+ 读 KV cache，和算力取慢的那个，再加通信：
  8 卡以内张量并行，每层两次 all-reduce；超过 8 卡的 MoE 走大规模专家并行，每层一次 all-to-all；
  副本超出 scale-up 域的部分走网卡，带宽掉一个数量级
- MTP 投机解码：每步每个请求多验 1–3 个草稿 token，接受率按 75%、56%、42% 算，多验的位置要多算、MoE 还要多读专家
- 预填充按算力算；Agent 任务里八成上下文命中前缀缓存，只算新的部分，但新 token 照样要看完整的上下文
- 首 token 延迟 = 调度 + 预填充 + 和别的请求抢预填充 + 等解码槽位（M/M/c 排队近似），p99 按经验系数放大
- 一个副本能扛的请求/秒 = 首 token 和每 token p99 都在 SLO 内的最大到达率
- 冷启动 = 2 分钟初始化 + 每台机器 3 GB/s 读权重
- 加速卡的规格取厂商公开的数字，Rubin、MI455X 的 BF16 这类没公布的按同代 FP8 的一半估；
  价格是每卡每小时的游戏值，按 2026 年包年行情取整，新卡按首批溢价算
- 预算和单价目标按模型定：每种卡挑一个最省的副本配置，单价最低的几种各让老周调一遍扩缩容跑一天
  （新卡数量少、扛不住高峰的会被刷掉），取花得最少的那个当参考，预算给它的 1.2 倍，单价给 1.08 倍
- 一天按分钟推进：流量按作息曲线（发布会叠一个尖峰）加噪声，自动扩缩容每 2 分钟最多加 8 个副本，
  副本平均每卡 8,000 小时出一次问题（掉卡、OOM、NCCL 超时），挂了自动补一个；能扛的量不够时请求排队，
  排队时间加到首 token 上，超过 SLO 的请求不算达标
