# 万卡集群模拟器

在浏览器里当一回大模型训练集群的值班工程师。

你要在期限和预算之内把一个模型训完。开跑前先配集群：GPU 型号、卡数、网络、存储，
再定并行策略（TP / PP / DP / EP）、全局批次、激活重计算、存盘间隔和备机数量。
开跑之后，一万张卡平均几个小时就坏一张：掉卡、ECC 错误、链路抖动、过热降频、loss 尖峰。
你要决定什么时候存盘、留多少备机、换不换慢机器、要不要回滚。

## 玩法

- **开局配置**：左边选任务，中间配集群，右边实时给出工期、花费、单步耗时拆解、每卡显存，
  集群负责人老周会指出配置里的问题。配置不成立（除不尽、显存不够）时不能开跑。
- **值班**：机房是一个等距视角的沙盘。8 卡一台机器，4 台一个机柜，两排背靠背一组，
  每个机柜顶上的四颗灯就是四台机器。降频和故障的机柜上会立起标记，点机柜能看每台机器的状态，
  降频的可以一键换下（先存盘，再用备机顶上重启）。
- **故障**：作业回滚到最近一次存盘。有备机大约 10 分钟恢复；备机用光了，就得停 3 小时等现场修。
  坏机送修 12–48 小时后回到备机池，所以卡越多，需要的备机越多，开局预估会按坏机速度算出该留几台。
- **过热降频**：同步训练要等最慢的那台，全集群按 0.62 倍速跑。七成会在 2–8 小时内自己降下来，
  剩下的要换。卡多了手动换不过来，可以在底栏打开“降频自动换下”（1 或 4 小时后自动换）。
- **loss 尖峰**：自动暂停，二选一：回滚并跳过这批数据，或者先观察（四成会发散，尖峰后的存盘作废）。
- **验收**：按期交付才评级。Goodput ≥ 85% 和花费 ≤ 预算 90% 两条都满足是 S，满足一条是 A，都不满足是 B。
  验收页有整局的时间线，还会把时间拆成有效训练、降频拖慢、重启、等维修、存盘、回滚几块。

快捷键：空格暂停，1/2/3 切速度，S 存盘，B 加备机，C 改配置，Esc 关掉机柜详情；loss 尖峰时按 1 或 2 选。

任务：70B 基座（入门）、405B 万卡（困难）、671B MoE（专家）。

## 运行

纯静态页面，没有构建步骤：

```bash
npm start          # 等价于 python3 -m http.server 8000
# 打开 http://localhost:8000
npm test           # 性能模型和机房排布的单元测试（Node 18+）
```

## 代码结构

- `src/sim.js`：性能与可靠性模型，纯函数，可在 Node 里测试
- `src/scene.js`：等距机房的排布和 canvas 渲染（机房本体缓存成一层，每帧只画灯、高亮和人）
- `src/game.js`：游戏循环、事件、界面
- `index.html`：页面结构与样式
- `tests/`：模型和排布的测试

## 模型说明

数量级对、取舍有意思，不追求逐包仿真：

- 计算时间 = 6 × 激活参数 × token / (卡数 × 峰值 × 内核效率)，重计算多算 1/3
- TP 每层 4 次激活集合通信，≤8 卡走 NVLink，否则走网卡
- EP 的 all-to-all 按 top-k 拷贝计流量；每卡专家越多，GEMM 越碎、效率越低
- 流水线气泡 = (PP−1) / 微批次数；DP 梯度同步约 70% 与反向重叠
- 显存：bf16 权重 + fp32 梯度 + Adam 状态按 DP 切分（ZeRO-1）+ 激活
- 故障率按单卡 MTBF 线性放大；存盘间隔可对照 Young 公式 √(2·C·MTBF)
- 备机池按泊松分布估算用光的概率：送修中的机器 ≈ 坏机速度 × 平均送修时长
- 全局批次超过临界批次后 token 利用率递减；loss 用 Chinchilla 拟合
- 各任务的预算和期限用和游戏同样规则的蒙特卡洛模拟校准过
